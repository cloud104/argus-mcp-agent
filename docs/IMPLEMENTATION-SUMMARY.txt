================================================================================
🎯 PRINCIPAIS CARACTERÍSTICAS
================================================================================

GESTÃO DE CONFIGURAÇÃO BASEADA EM .ENV
--------------------------------------
✓ TODO o sistema usa .env como fonte única de verdade
✓ Docker Compose: carrega .env automaticamente
✓ Tilt: lê .env e gera ConfigMap/Secret dinamicamente
✓ Make: comandos criam secrets K8s a partir do .env
✓ Script: generate-k8s-secret.sh cria secret.yaml do .env

CHROMADB - DUAS OPÇÕES
---------------------
✓ Modo Embutido: ChromaDB como biblioteca (desenvolvimento)
✓ Modo Standalone: ChromaDB como serviço separado (produção)
✓ Configurável via Helm values (chromadb.enabled: true/false)
✓ Suporte em todos os métodos de deployment

SEGURANÇA
---------
✓ Imagem de produção: distroless (sem shell, minimal)
✓ Non-root user: uid 65532 (distroless) / 1000 (dev)
✓ Multi-stage builds: reduz tamanho e superfície de ataque
✓ Secrets: nunca commitados (.gitignore)
✓ Security contexts: aplicados em todos os deployments

DESENVOLVIMENTO
--------------
✓ Hot-reload: code changes → automatic rebuild/reload
✓ Debugging: debugpy em portas separadas (5678, 5679)
✓ Tilt UI: monitoramento visual em localhost:10350
✓ Live sync: Tilt sincroniza arquivos sem rebuild
✓ Manual triggers: testes, linting, formatação

PRODUÇÃO
--------
✓ Autoscaling: HPA baseado em CPU/memória
✓ HA: pod anti-affinity, multiple replicas
✓ Ingress: suporte SSL/TLS com cert-manager
✓ Health checks: liveness e readiness probes
✓ Resource limits: CPU e memória configurados
✓ PDB: pod disruption budgets (produção)

================================================================================
📚 FLUXOS DE TRABALHO
================================================================================

1. DESENVOLVIMENTO LOCAL
   $ make setup
   $ source .venv/bin/activate
   $ uvicorn main:app --reload  # Terminal 1
   $ uvicorn tools.server:app --port 8002 --reload  # Terminal 2

2. DESENVOLVIMENTO COM DOCKER
   $ make setup  # cria .env
   $ make dev    # docker-compose up
   Ou:
   $ docker-compose -f docker-compose.chromadb.yml up

3. DESENVOLVIMENTO COM TILT
   $ make setup  # cria .env
   $ tilt up     # lê .env, gera secrets, deploya

4. DEPLOY KUBERNETES MANUAL
   $ make generate-k8s-secret     # gera secret.yaml do .env
   $ kubectl apply -f k8s/dev/

5. DEPLOY COM HELM
   $ make create-k8s-secret       # cria secret do .env
   $ make helm-install-dev

================================================================================
🔐 GESTÃO DE SECRETS
================================================================================

DESENVOLVIMENTO
--------------
Fonte: arquivo .env
Métodos:
  1. Tilt: gera automaticamente do .env
  2. Script: ./scripts/generate-k8s-secret.sh
  3. Make: make generate-k8s-secret
  4. Kubectl: make create-k8s-secret

STAGING/PRODUÇÃO
---------------
Métodos recomendados:
  1. External Secrets Operator (AWS/Azure/Vault)
  2. Sealed Secrets (criptografado no git)
  3. Manual kubectl (menos recomendado)

IMPORTANTE
----------
✗ NUNCA commitar .env
✗ NUNCA commitar secret.yaml
✗ NUNCA usar secrets de prod em dev
✓ Usar .env em desenvolvimento
✓ Usar External Secrets em produção
✓ Rodar secrets regularmente
